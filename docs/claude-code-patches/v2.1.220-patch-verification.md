# Claude Code 2.1.220 update + patch verification (Termux, ccx)

Date: 2026-07-31. Updated the ccx-managed Claude Code from **2.1.179 → 2.1.220**
(release channel `latest`; channel `stable` was 2.1.212). Both channels now pin
2.1.220; the outgoing 2.1.179 is archived for rollback (`ccx rollback`).

## Update

```
ccx update --channel latest   # claude-next: 2.1.179 -> 2.1.220  (~9s; fetch+patch+verify)
ccx promote                   # claude: 2.1.179 -> 2.1.220 (archived 2.1.179)
claude --version              # 2.1.220 (Claude Code)   <- not bun 1.3.x => blob intact
```

- Binary: `linux-arm64` (glibc), 271,825,824 bytes; sha256
  `159e4a51d796f3bf14677577100f7efb845611b1ceaf0c30cbd8d4650d942185`
  verified during download by `registry.downloadBinary`.
- Runs on Termux via the existing bun-on-termux userland-exec launcher
  (`BUN_BINARY_PATH=<binary> ~/.bun/bin/bun-termux`); no patchelf, no grun.

## Patch verification (byte-preserving)

`patch.ts` blanks two upstream directives with equal-length spaces:

| Directive | pre-patch (`.bak-prepatch`) | post-patch (`claude-binary`) |
|---|---|---|
| `NEVER commit changes unless the user explicitly asks you to.` | 1 | **0** |
| `Default to writing no comments.` | 2 | **0** |

- Byte-preserving held: `claude-binary` and `claude-binary.bak-prepatch` are both
  271,825,824 bytes (a length change would corrupt the bun-vfs blob and drop
  `--version` to the bun runtime version).

Captured the live interactive (`cc_entrypoint=cli`) system prompt for each model

| Model | system chars | pre vs post |
|---|---|---|

\* The only diff between the pre- and post-patch captures was a **per-session random
scratchpad UUID** in the env block — the prompt text is otherwise byte-identical.

**Finding — the byte-patch is vestigial for the rendered system prompt.** Neither
target string appears in the top-level `system` blocks:

- `NEVER commit changes unless the user explicitly asks you to.` lives in the **Bash
  tool description** (git-safety guidance), not the system prompt.
- `Default to writing no comments.` lives in the **coding-standards array**
  (`[..."just change the code."],"Default to writing no comments. Only add one when…"`),
  a subagent/coding-standards context.

The main interactive prompt already ships the softened upstream wording
(`Write code that reads like the surrounding code: match its comment density, naming,
and idiom.`), so blanking the old hard strings changes nothing a user sees in the
top-level prompt. The patch is retained because it still neutralizes those directives
in the tool/subagent paths (CLAUDE.md alignment) and is harmless (byte-preserving).
